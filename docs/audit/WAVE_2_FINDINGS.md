**KV-AUD-222 | S2 | Confirmed (revises 055/164/165/203) | L1/L9 | `combat.tsx:1019-1024` + render `:1236`** — **`rewards.xp` is NOT vestigial — it is consumed as stat proficiency, but physical-only.** `handleVictory` computes `xpPerStat = Math.floor(rewards.xp / 4)` and `addPendingExcelia` to **STR/END/AGI/PER only** (`:1021-1024`); the victory UI shows "+{rewards.xp} to combat stats" (`:1236`). **KV-AUD-226 | S3 | Confirmed (056 safe but fragile) | L6 | `combat.tsx:991-1158`** — **The rewards-clear race is safe in practice.** `handleVictory` reads all of `rewards` (gold `:1002`, materialDrops `:1008`, xp `:1020`, weaponDrop via the pickup handlers) and finishes distribution **before** `endCombat()` nulls it (`:1156`, immediately before `router.back()`). **KV-AUD-227 | S2 | Confirmed | L6/L10 | `combat.tsx:1386-1414` + `handleDefeat:1161-1196`** — **Permadeath is not committed until the player taps "Accept Fate."** Reaching `phase==='defeat'` only renders the FALLEN screen; the irreversible calls — `endRun('death')` (`:1175`), `discardExcelia()` (`:1178`), `killCharacter()` (`:1181`) — run **only inside `handleDefeat`**, the button handler (`:1407`). **KV-AUD-228 | S3 | Confirmed | L1/L6 | `combat.tsx:977-986`** — **Latent weapon id mismatch on "Add to Bag."** `handleAddToBag` calls `registerWeapon(rewards.weaponDrop)` (`:977`) — which keys the registry by `weaponDrop.id` — but then `addToInventory` stores the item under `id: rewards.weaponDrop.id || weapon_${Date.now()}` (`:979`). **KV-AUD-230 | S2 | Confirmed | L5 | `combat.tsx:99-141`** — **Unselected full-store subscriptions.** The screen destructures `useCombatStore()` (`:99-136`), `useCharacterStore()` (`:138`), `useDungeonStore()` (`:140`), `useAchievementStore()` (`:141`) with **no selector functions**, so *any* state change in those stores re-renders the entire ~3,100-line combat screen and its heavy child tree (`MonsterDisplay`, multiple `DramaticReveal`s — cross-link the unmemoized-render concern 033). **KV-AUD-231 | S3 (latent → S1 if self-damage exists) | Confirmed | L1 | `combat.tsx:144-148`** — **A simultaneous kill-and-die resolves to DEFEAT, voiding the win.** The reactive death effect sets `'defeat'` whenever `currentHP<=0 && phase !== 'defeat' && phase !== 'fled'` — it does **not** exclude `'victory'`.
